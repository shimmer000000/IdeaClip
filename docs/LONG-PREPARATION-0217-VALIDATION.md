# 0.2.17 长截图准备与变化提示

日期：2026-11-10；基线84d499648d7c0611dfbdd3256468fb13854d38f1（0.2.16）。开始工作区干净。

## 证据与问题

用户截图已不再是后台方式错误，而是“页面尺寸或内容高度发生变化”。该提示合并了URL、DPR、视口及文档尺寸变化，不能由截图推断具体变化项，更不能声称已经读取或复现用户网页。

在合成页面复现一种确切原因：滚动触发新增100 CSS像素内容，0.2.16立即拒绝。新增单元先在旧实现失败，再实现准备期与正式截图分离；不是在拼接中接受变化或保存半成品。

## 修复流程

1. 安装原有取消、样式暂停和滚动恢复控制，核对当前页面及长度限制。
2. 在本次整页/当前分段的有限范围逐屏准备，最多40次；不调用captureVisibleTab、不分配图片画布。仅在此阶段允许正文高度稳定，仍拒绝URL、视口、缩放及横向变化。整页或单段长度上限不扩大，不自动继续下一段。
3. 返回本次起点，最多2秒，每200ms测量一次，连续3次全部测量字段一致后建立正式截图基线。准备时的高度变化不混入最终图片。
4. 此后仍逐帧严格比较基线、前后位置、活动标签与URL；再次变化则停止、恢复、无半成品，不自动重试。
5. 错误区分网页高度、可视区域、缩放、宽度、地址变化。高度/视口仅显示有限数字；不输出地址、正文、表单或凭据。

保留90秒看门狗、取消清理、每次截图600ms间隔、40张截图和原画布/压缩上限。预加载会增加等待与滚动，也可能触发网页自身网络加载；插件没有新增搜索/AI/任意抓取接口。连续加载、内容替换、虚拟列表或不稳定页面仍可能拒绝；尺寸稳定不证明内容绝对静止或事实完整。

## 数据与安全

不修改数据库、旧截图、采集记录、笔记、报告或预算。不增加依赖、权限、后台任务，不调用付费API。页面关闭/导航仍只能尽力清理；不承诺所有动态网页可截图。含分段的ZIP规则沿用0.2.15，旧备份仍保留。
