## 实现及操作范围

- 已保存灵感（编辑页/完整笔记）、研究计划、AI商业报告、孵化项目均保留原入口并新增“启动深度研究”。`notes.html?research&wizard`是统一八步页面；从原研究进入按稳定研究ID继续已有向导，不自动重建或覆盖。
- 八步为目标、调查计划、范围、采集、人工审核、AI综合、商业报告、孵化任务。显示进度、当前状态、下一步与保存历史；保存目标/本步/项目草稿后可重开继续。未保存编辑离开前提醒，不宣称未提交输入自动恢复。
- 九类初始问题由本地规则生成，复用原generateOutline候选词，默认取前三项以符合3次搜索上限。九类问题、原有问题与关键词均可修改；原有问题单独保留，研究sources/notes及竞品/GitHub原提纲不被新九类问题覆盖，历史版本保留。全部问题合计仍受原研究10000字符字段限制，超限拒绝而非丢弃。
- 第3/4/6/7步嵌入原OnlinePanel的对应操作，复用OnlineResearch/ResearchAdapter/Proxy和AIEngine，不在向导另写fetch/模型执行器。联网默认关闭，采集仍须展示全部操作、精确白名单、数量及预算后逐次确认；AI是另一笔独立确认。保留免费health、暂停/取消、3次搜索/5页上限、来源读取状态、错误和费用未知不重试机制。
- 第5步按已读取/部分/摘要/不可读/失败筛选，显示来源URL、问题、摘录、公开/采集时间、哈希和信息缺口。选1–10份可读资料且主动勾选人工审核后才进入综合；不可读/失败不能选择。摘要不冒充全文，哈希不证明真实事实。
- 人工审核绑定整个研究计划和规范来源全快照（不仅正文）；AI预览/预算事务/发送前/返回后复查向导、计划与所有来源，变更、缺失或损坏使旧确认失效。预算、权限与总开关仍由原引擎门禁处理。

## 十二栏商业报告与孵化

新研究报告Schema v2包含核心结论、商业模式、市场需求与目标用户假设、竞争产品、主要证据、反证、初期投入假设、盈利路径、风险、未验证事项、7天计划与MVP。使用构建时Ajv静态校验，无运行时eval；仍检查实际来源ID、逐字quote、原文相等和未知链接。资料仅作为不可信user数据，固定system安全规则不由网页改变，不调用工具或执行命令。

旧八栏schema1、旧AI商业报告、对比和项目方案继续按原结构展示。新报告保存workflowId、研究版本、时间/模型与来源快照，可查看历史、复制及Markdown导出；AI写入失败仍可只重试保存。若报告已成功写入但步骤更新前窗口中断，第6步可主动“使用已保存报告继续（不请求AI）”，不为恢复进度重新计费。

选择十二栏报告生成项目草稿，字段/任务建议可编辑，长的模型建议节选会标记，完整报告仍保留。人工填写的项目描述和风险分别完整保存，不把风险追加后截断用户描述。须人工审核字段/风险/任务再创建。复用createProject/saveProject/validateProject；项目、向导projectId及完成进度同事务，失败回滚，不留下空项目，重复提交不能新增第二个项目。旧报告与当前来源/计划不一致时拒绝转换，保留旧报告供查看。

项目增加可选researchOrigin与researchRisks；来源删除后项目/任务保留，提示缺失/变化。进入原项目中心可以复制中文Codex指令，风险随背景文字提供；没有Codex执行器、自动GitHub建库或阶段自动修改。

## 持久化、迁移和恢复

Dexie14仅新增researchWorkflows。每研究一个向导，保存revision、步骤/完成情况、问题/请求草稿、审核摘要、报告/项目软引用、项目草稿、错误/暂停说明及最多100条步骤历史。并发版本检查避免旧页面覆盖，失败保留当前输入。原研究版本、笔记、Blob、报告、任务、账本与配置不重写。

ZIP6新增向导表，兼容v1–v5/schema≤13；v13→14和真实旧ZIP5缺少向导计数的导入已测。字段白名单及脱敏排除未知执行字段，恢复清空review/planHash/待读URL、暂停状态、步骤最多5且只保留审核前完成标记，保留历史/项目草稿/报告引用。不能把历史/已保存审核字段当付费执行资格。原隔离校验、哈希、二次确认替换和事务回滚复用；配置、密钥和预算不导出或重置。

关闭页面只保留已提交步骤。网络任务中断仍在原researchRuns标记暂停/未知，不重发；向导重新打开不会调用搜索/模型。只有明确未发的操作可走原重新预览确认。客户端取消不保证服务商停止计费。

## 测试结果

新增16项单元/集成覆盖本地计划编辑/原问题与人工资料保留、并发/重复入口、来源人工审核/失效（正文/问题/删除/计划）、十二栏Schema与伪造来源、AI总开关/预算/取消、Mock综合到项目/任务/Codex、旧报告拒绝冒充新分析、写入失败原子回滚、ZIP6/旧ZIP5、v13→14及恢复执行字段清除。原迁移测试仅更新当前schema与未来版本断言，保留旧数据校验。

Chrome新增4项独立配置测试：

1. 目标/计划编辑 → 确认范围 → Mock搜索与公开正文 → 人工审核 → 取消AI预览零请求 → 单次确认生成十二栏报告 → 人工改项目草稿 → 创建项目与任务 → 原Codex指令复制 → 重开不重复创建；另模拟已保存报告但步骤未推进，免费接续到报告步骤，AI总请求仍只有1次。
2. 未授权零请求，保存请求草稿后完全关闭独立Chrome再重开，步骤/文本保留，不自动开始付费任务。
3. 删除真正已审核来源后拒绝AI；ZIP导出/二次确认替换/重开退回审核，审核和执行资格不恢复。
4. 已保存笔记、研究计划、AI报告和项目四类入口正确；缺失或草稿来源不由新向导绕过原resolveRef校验。

初轮缺失来源测试删除了随机来源而非审核中那条，改为按向导review ID删除；单元夹具也修正URL规范化、正文/摘录同步和恢复函数参数，不放宽业务断言。4项Chrome专项通过，完整报告布局已截图检查。所有搜索/AI上游都是本机Mock，非本机网络拦截，检查页面错误与凭据日志。本阶段没有重新请求用户安装或相同手动测试，没有真实付费调用。

## 边界与遗留

- 真实Brave搜索、真实模型返回、端点兼容性/费用仍未获逐次授权，不标通过；IC-014的三个真实公开读取结果不等于本轮完整真实付费工作流验收。本轮完整工作流只有Mock证据。
- 原生网站权限弹窗、普通安装所有权限跨重启、Edge、全面无障碍、移动/多DPI、长期大量向导未专项验收。沿用已有用户Chrome整体确认，不扩大证据范围。
- 向导历史最多100条，研究原字段/源数及AI200000字节限制继续有效；超限明确拒绝。列表最近30个向导，较早记录可从原研究入口/稳定ID打开；报告最近30份，来源分页50份。
- 研究初始计划仍是本地规则，不是AI预先调查。用户必须主动保存本步；本机健康不证明Brave账户可用。保持原服务窗口与执行页面打开，不在后台自动扫描网页/历史或执行任务。
- 同一向导已生成项目后不自动重建已删除项目；如需另建可在项目中心人工处理。项目来源哈希只提示快照变化，不作为真实事实签名。删除原研究后孤立向导/报告仍保留在数据库与备份，现有向导页不能继续已删除的计划；不会自动重建或覆盖。
