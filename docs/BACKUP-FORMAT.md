# IdeaClip 备份格式 v2（兼容 v1）

IC-005 使用标准 ZIP32 的受限 STORE 配置，无加密、无压缩、无分卷，不依赖外部服务或解压库。通用 ZIP 工具可以查看文件，IdeaClip 导入只接受符合本格式的文件。不要用通用工具重新压缩或修改备份；不满足格式、版本或完整性检查时会拒绝。

## 文件结构

```text
manifest.json
data/notes/000000.json
data/noteDrafts/000000.json
data/screenshots/000000.json
data/contentCaptures/000000.json
data/settings/000000.json
data/analyses/000000.json
data/projects/000000.json
data/aiTemplates/000000.json
images/000000.png
images/000001.webp
```

数据分片编号与图片编号仅用于文件定位，业务 ID 始终保留。空表不产生分片。每个 JSON 分片为记录数组，通常 16 条，过大时再拆分；截图元数据额外包含 `image` 路径，二进制不转 Base64。文件名在应用中只作索引，不会写入任意文件系统路径。

`manifest.json` 包含：

- `format: "IdeaClip"`、`formatVersion: 2`（当前导出；继续读取 v1）。
- `databaseVersion`：导出时 schema 版本，当前 9；导入支持 1 至 9，拒绝未来版本。
- `createdAt`：ISO 备份创建时间。
- `counts`：七个业务表的完整记录数，包括 0。
- `entries`：除清单自身外每项的 `name`、字节数 `size`、小写十六进制 `sha256`。

ZIP 还提供每项 CRC32。校验和用于发现传输损坏，不能证明来源可信。清单中的数量、文件列表、尺寸、记录类型、图片与关联均独立校验；重复路径、重复 ID、缺失图片、无用图片与缺失引用拒绝。图片签名、尺寸与元数据必须一致，并在 Chrome 中实际解码检查。

## 数据范围与脱敏

当前导出八个权威表：`notes`、`noteDrafts`、`screenshots`、`contentCaptures`、`settings`、`analyses`、`projects`、`aiTemplates`。`body` 保留为感悟，`content` 是采集正文，稳定 ID、标签、收藏、保存状态、时间、图片和采集关联不合并或改名。

schema v8 采集可含 `quality.version: 1` 和 `provenance.version: 1`。备份按脱敏后的正文与 URL 重算质量和有界段落位置，丢弃 DOM 路径，来源强制标记 `backup`；不携带自动发送资格。恢复后仍可编辑和逐次确认手动分析。旧采集没有这些字段时保持兼容；未来元数据版本或非法指标拒绝导入。定位与校验和均不证明网页事实真实。

逐字段白名单投影，不导出未知配置字段。设置仅包含 `general.aiEnabled`；API Key、访问令牌及其他未知凭据配置不会进入备份。文本中常见密钥、Bearer、私钥块和凭据赋值作脱敏，URL 中 token、secret、password、API Key、authorization、credential、signature 查询参数移除；普通原始 URL 保持原文本。脱敏字段不能逐字恢复，且不能保证识别任意人为格式或截图中的秘密。备份不加密，请妥善保存。

浏览器标签 ID 不可跨浏览器复用：笔记、草稿及采集的 `sourceTabId` 置空，截图置 0。用户从原网页重新连接后继续截图。不导出 `noteCatalog`、`noteSearch`、`draftCatalog`、`libraryState`、`screenshotThumbs`，恢复时重建目录、搜索和未提交编辑索引，缩略图按需生成。

schema 1 至 3 的早期笔记缺省字段通过当前默认模型补齐，旧 `body` 不迁移为正文。主数据库由 Dexie 的 v1 至 v9 迁移链升级，备份功能不重置现有主数据库。

IC-007 增量升级到 schema v6，保留旧数据并增加 AI 配置、用量表及分析历史复合索引。`analyses` 的可选字段包含 `report`（15 栏结构化 JSON）、`model`、`provider`、`endpointOrigin`、`inputDigest`、`inputRevision`、`imageCount`。结构化报告先做 Schema 校验，再逐字段脱敏，从脱敏报告重新生成 Markdown，避免 Markdown 转义隐藏令牌。旧 `content` 纯文本报告继续兼容。

`aiConfig`、Chrome 会话/本地凭据、`aiUsage` 不导出。恢复到新设备须重新配置、授权服务商；完整替换保留本设备 AI 配置和预算账本，不能借由恢复重置本地每日预算。恢复动作会通知 AI 引擎取消未完成请求和排队任务，已发送请求仍可能计费。

IC-008 的 schema v7 新增本设备自动授权与任务表，不改变上述七表文件格式。`autoPolicy` / `aiTasks` 不导出，不随备份启用自动请求；恢复前暂停队列，替换保留这些表及当前 AI 配置、账本。恢复后人工恢复仅限尚未发送且快照/来源/权限仍有效的任务；费用未知、已失败或已取消任务不自动执行。

## 合并与替换

校验后的数据存入随机命名的隔离临时数据库 `ideaclip-restore-stage-…`。正式恢复前不写入主业务表。恢复预览受 Web Lock 保护，其他设置窗口不会清理正在使用的暂存。取消、成功后释放；进程退出后遗留的闲置暂存库下次进入设置时清理。

合并在主数据库事务中重新判断当前数据，避免预览期间的变更被覆盖：

1. 同表稳定 ID 相同且白名单可移植内容相同，判为重复，保留本地。截图还比较完整二进制 SHA-256。
2. 同 ID 内容不同，或草稿的唯一 `entryKey` 被另一 ID 占用，判为冲突。设置冲突独立保留本地。
3. 对备份中的笔记、草稿、图片、采集、历史分析与项目构建引用分组，冲突影响整个相连分组。相同内容的已有记录仍计为重复，其余分组记录跳过，不把新笔记接到本地的另一版本截图或采集。
4. 无冲突新记录插入，保留 ID。重复、冲突和关联冲突的数量明确显示；不自动重命名，也不覆盖已有版本。

完整替换需要界面二次确认。当前八个业务表、派生索引及缩略图的清空与新记录写入位于**同一 IndexedDB 事务**；搜索索引与管理目录也在该事务重建。合并也使用单个完整事务。任何写入失败、配额不足、取消或事务中断会整体回滚，不存在一半替换的成功状态。

主事务分批从另一数据库读取暂存数据，使用 [Dexie.waitFor](https://dexie.org/docs/Dexie/Dexie.waitFor()) 保持目标事务活跃；不在等待期间访问目标事务对象，不等待网络、用户确认或整包解压。主数据库写入锁在恢复事务期间阻止并发写入；恢复完成会通知管理页重新加载。恢复前应关闭其他编辑窗口，成功后重开编辑页，避免旧界面继续编辑旧版本。

## 安全与资源边界

| 项目 | 上限/规则 |
| --- | --- |
| 整包 | 512 MiB，非 ZIP64 |
| ZIP 文件数 | 10000（包含清单） |
| 单项数据 | 8 MiB |
| 业务记录 | 100000 |
| 记录间引用 | 500000 |
| 图片 | PNG / WebP，单边 ≤8192，像素数 ≤16777216 |
| ZIP 条目 | UTF-8 标志、STORE、压缩与未压缩尺寸相同、无数据描述符 |
| 路径 | 只接受上述白名单路径和六位数字文件名，拒绝重名、绝对路径、上级路径 |
| 目录 | 校验中央与本地记录一致、边界及顺序，无重叠、额外未声明数据或注释 |

STORE 配置无需解压，因此压缩炸弹在解析阶段被拒绝；尺寸欺骗、过多引用、超大像素图片在装载或解码前拒绝。HTML 字符串只作为业务文本保存，不执行脚本，不把备份路径交给文件系统，不下载外部媒体。

导出在同一只读事务中每批读 16 条，收集 JSON 分片和原始 Blob 句柄构成一致快照；摘要和 CRC 逐项计算，避免物化全部图片字节。恢复逐项校验并落到暂存，每批 16 条搬入主事务，不一次性在 JavaScript 中保留全部原图或正文对象。引用检查与冲突图保留轻量 ID 信息。浏览器可能为 Blob 分片和 IndexedDB 事务使用额外内存与磁盘空间；达到上限并不表示所有设备均可无等待处理。

源库关联缺失、格式错误、超限、空间不足或未知版本会明确失败，不删除原主库。完整替换成功后无法用界面撤销，必须由用户先保留当前 ZIP。加密、增量备份、云同步和超过上述上限的数据分卷不在本阶段。


## IC-009 模板与报告兼容

ZIP v2 新增 `aiTemplates`，包含自定义模板和已保存的内置启停记录；应用内置默认定义由版本化代码提供。单模板按 24 KiB 及受限字段、栏目和变量校验，整包最多 105 个模板记录。导出不包含默认选择与本机偏好版本（`skillPreferences`）、自动策略、任务、配置、凭据或账本。模板字段和报告快照先脱敏，新写入的模板恢复后强制停用，不能导入执行授权；合并时跳过的本地重复记录保留本地启停状态，但旧自动授权同样失效。

`analyses` 可包含 `template` 定义快照及 `skillReport.schemaVersion: 2`；按快照 Schema 校验、逐条脱敏并重建 Markdown。旧 v1 15 栏报告与早期纯文本继续可读。历史快照不引用可变的本机模板表，因此删除模板不丢失报告或导致关联缺失。

旧 ZIP v1/schema≤8 没有模板计数时视作 0，原 CRC/SHA、图片和关联检查仍完整执行；新格式必须明确给出模板计数。完整替换旧备份会移除当前模板记录，界面确认范围包含模板，用户应先导出当前备份。恢复事务同时轮换本机偏好版本、使自动模板授权失效；默认选择保留本机值，目标模板不存在/停用时需重新选择及授权，不静默切换执行模板。合并的同 ID 冲突保留本地，导入单模板 JSON 则另建 ID，二者语义不同。
