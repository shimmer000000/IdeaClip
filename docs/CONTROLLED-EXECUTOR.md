# 受控执行器与运行时边界 · 0.2.2

## 当前结论

本版建设独立本地控制器及**固定合成程序**隔离测试。真实Codex执行入口始终`REAL_EXECUTOR_DISABLED`，没有可签发真实执行许可的实现；即使提供任务包、Mock许可或口头批准，也不能使该入口启动进程。浏览器仅展示拒绝策略及原有Mock门禁，没有本机命令接口、网络服务或Native Messaging桥接。

Windows实际未取得可承载Codex的OS级文件系统和出站网络边界证据。不能把Codex `workspace-write`、普通子进程、预检或执行后扫描当作子目录沙箱。当前真实隔离验收为**未通过/阻塞**，不是以合成能力测试替代。

## 两层设计

1. `tools/controlled-executor.ts`是Node24+本地控制器。`createSyntheticExecutor()`只新建仓库自身`test-results/controlled-executor/synthetic-*`中的合成Git目录。没有接受现有用户工作区的执行构造器、导入命令、任意脚本、任意可执行文件或WASM输入。任务包v1和交付v2未改变。
2. `tools/synthetic-worker.mjs`是受信任的固定Node子进程宿主（沿用worker文件名），加载源码内固定WASM字节；不是任务代码，也不使用用户文件中的程序。来宾只有`cap.request(i32)->i32`导入，无WASI、内存共享、文件读取、网络、环境、进程或动态代码接口。没有宿主路径/凭据传给来宾。子进程使用固定Node绝对路径、固定脚本与内存/栈参数、shell=false、空环境、忽略标准输入/输出/错误及专用IPC；JSON中的任何命令/路径都不传给进程。固定Node子进程宿主具有普通Node权限，**必须保持受信任**；子进程本身不隔离恶意JavaScript。

来宾能力0只能申请固定合成结果；1（范围外写入）、2（主机读取）、3（网络）、4（子进程）及未知编号均由导入能力在运行时返回拒绝。它们不是对真实主目录/SSH/浏览器文件的试读，也没有发网络包。受信任broker仅在固定结果结构完全匹配后独占创建`docs/result.txt`，复查路径组件无链接、任务快照未变，使用`wx`禁止覆盖旧文件。没有把来宾提供的路径交给`fs`。

合成文件范围外拒绝由**不授予能力**实施，不是允许越界写入后回滚。实际文件哈希前后比对是第二层审计，仅覆盖合成工作树（跳过Git内部目录），最多100节点、深度8、单文件64KiB，超限拒绝；不代替运行时限制或全盘取证。对同权限恶意宿主代码、管理员、V8漏洞和外部文件系统竞态不作防护承诺。真实执行仍被阻止。

## 单次授权和生命周期

控制器复用0.2.1本地预检与私有对象身份门禁。项目/任务/包ID、包SHA-256、仓库、绝对目录、独立允许范围、分支、HEAD、索引、脏状态、CLI/合成程序标识均绑定快照。合成程序标识明确为`Fixed WebAssembly guest, NOT Codex`，不得冒充真实CLI探测。

预览5分钟，单次Mock许可默认2分钟、最多5分钟；墙钟与单调时钟校验。许可只在同一受信任本地实例内存中有效，不能用JSON复制/伪造/持久恢复，任务包始终`executionAuthorized=false`。独立确认和快照复查后签发；先消费再执行，执行前再次预检，目录/Git/任务变化失效。不自动续期、后台循环、重试、部署、推送或网络调用。

一次实例最多20份结果，同时最多1次运行。固定程序模式仅`success/timeout/crash`，不存在传命令或执行回调参数；来宾固定Node子进程使用32MiB V8老生代和1MiB栈上限（不是OS总内存限制），运行超时100～5000ms（默认1000ms），取消或超时后等待子进程`close`事件再返回。预检沿用0.2.1独立超时；取消后尚未结束的只读Git探测纳入清理等待，不提前删除其合成目录。无实际Codex模型进程启动。

结果为`IdeaClipSyntheticExecution` v1，仅保留项目/任务/包哈希/仓库/绑定摘要、运行ID/时间/耗时、安全状态码、变更相对路径、拒绝能力及固定false/0声明；无命令、正文、日志、凭据、绝对工作目录或授权对象。只写同一合成目录的独立JSON，最多20条；原始包/Git状态校验未通过时不生成“已经执行”结果。`close()`只清理工厂自有路径，先等只读探测结束；不清用户数据库、账本或其他项目。

这些是**合成执行证据，不是Codex交付v2、GitHub核实或人工验收**。不会自动进入真实任务或将任务完成。后续真实交付仍须经过现有受限导入与人工核对。

## CLI与未来接口

`npm run handoff:executor -- preview`或`--help`只输出阻塞预览，不创建任务/授权或启动合成子进程。任何其他参数（包括`exec`、任务JSON、`--yes`）均退出码2。合成执行仅由受信任测试代码使用工厂API，不提供命令行自动批准入口。

未来可设计的参数数组为：`['exec','--cd','<isolated-workspace>','--sandbox','workspace-write','--json','-']`。它**只是帮助信息核对后的接口草案**，没有启动器，不是用户可直接运行的授权命令；禁止shell字符串拼接、危险高权限参数或从JSON取得可执行文件。`workspace-write`不满足精确范围要求。当前CLI只执行`--version`与`help exec`元数据查询，不能将这两个短命进程写成“操作系统中从未启动过Codex进程”。

未来真实许可必须独立绑定以上全部快照并通过可信本地确认、短期限、一次性消费和已审计隔离后才能签发。不得把当前Mock许可转换成真实许可；未知结果/失败必须烧毁许可，不自动重发可能产生用量的操作。

## Windows隔离方案评估

本机只读结果见[验收](CONTROLLED-EXECUTOR-VALIDATION.md)。本版未启用任何Windows功能、提权、修改防火墙/网络/用户ACL或安装容器。

可行后续方向是专用VM/Windows Sandbox：禁用网络/剪贴板等非必要集成，只提供合成输入和受限输出，独立账户/干净磁盘、不映射主目录或真实项目，再测试精确写入范围。微软文档支持[禁用网络及只读映射](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file)。这只是方案依据，未在本机部署或验收，不自动生成/启动`.wsb`。共享一个可写项目目录也不等于限制到其子路径。

Node权限模型只适合纵深防御；本机v24.22.0帮助没有`--allow-net`，不能拿其他Node版本/主分支文档当成本机网络隔离证据。官方也列出[权限模型限制](https://nodejs.org/docs/latest-v24.x/api/permissions.html)。本版不使用它来运行任务。
