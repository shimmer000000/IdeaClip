**0.2.3当前入口**：[受信任Windows本地单任务说明](CODEX-LOCAL-TASK.md)。用户取消额外OS隔离方案；下文是保留的0.2.1计时器Mock协议，其禁止真实执行的结论仅适用于旧Mock入口，不代表新增本地CLI已获具体任务授权。任务包/ZIP仍不携带执行授权。

0.2.2补充：[受控执行器协议](CONTROLLED-EXECUTOR.md)。下文保留0.2.1计时器Mock设计；新增独立本地固定WASM合成执行器不改变本门禁授权语义，仍禁止真实Codex执行。

本阶段只提供**一次性Mock授权门禁**。没有真实Codex执行器、后台服务、Agent Autoloop接口、自动付费或自动验收。任务包v1/交付v2保持不变，包内`executionAuthorized`仍必须为false。

## 本地真实预检

现有`handoff:local`保持原只读功能。新增一次性入口`npm run handoff:preflight -- --help`。需要Node24+及本仓库已有依赖，没有新增依赖。

```text
npm run handoff:preflight -- preview --package "<绝对任务包JSON>" --workspace "<明确工作目录>" --repository "https://github.com/owner/repo" --project-id "<已绑定项目UUID>" --task-id "<已绑定任务UUID>" --branch "<预期分支>" --allow-path "<已有允许范围>" --codex-executable "<已核实且受信任的Codex绝对路径>"
```

可重复`--allow-path`，最多20项。独立策略必须由操作者明确提供，不能从包自身自动扩大：项目/任务ID、仓库、目录、分支需匹配；包中每项范围必须等于策略路径或位于其内部。未明确给定策略、通配/越界/符号链接/目录联接均拒绝。

预检复用包Schema/哈希/契约、真实Git根和原始/有效origin校验；另读当前分支、HEAD、索引、状态和未合并项。未提交修改、合并冲突、分支不符、detached HEAD或CLI参数不支持均阻塞。过程中及消费前重新检查包、Git与CLI快照，不覆盖原修改、不fetch、不切分支、不提交代码。

允许目录内部也做不跟随链接的只读元数据扫描，单次≤2000节点、深度≤16，拒绝子级链接、嵌套仓库和特殊文件；超限报`SCOPE_SCAN_LIMIT`，不静默略过。指纹绑定目录/文件元数据，不输出文件内容。实际工作树中的文件型`.git`布局暂报`GIT_LAYOUT_UNSUPPORTED`，不会自动创建或修复用户worktree。兼容性仅在新建隔离Git样本中研究、验证安全拒绝。

CLI路径来自独立操作者输入，不接受任务包中的程序路径。仅对该明确受信任已安装工具执行`--version`及`help exec`两个元数据命令，校验帮助中`--cd / --sandbox / --json`，不传任务提示词、不运行`codex exec`。版本、帮助与文件元数据绑定指纹；参数存在不证明完整执行兼容性，也不证明未来sandbox能限制到单个文件。

`preview`输出`IdeaClipExecutionPreflight` v1及脱敏快照，绝对目录替换为匹配说明；交互确认前才在本机显示明确工作目录。无论输出如何复制/改写，它都不是授权载体。预览有阻塞退出码2，不提供自动修复、忽略脏状态或自动确认参数。

## 授权生命周期

`SingleUseMockGate`在一个页面/进程内维护私有WeakMap。预览和授权须为该实例生成的原对象，JSON反序列化、其他实例、伪造或修改预览对象无法匹配。没有可导入的授权JSON、可复制Bearer token、授权文件或持久密钥。

绑定包含项目ID、任务ID、包ID/内容哈希、仓库、明确目录/原策略范围、任务当前审核快照、Git HEAD/分支/索引/状态/范围元数据、CLI版本及指纹。任何变化均失效。浏览器另查当前数据库的已审核任务和已知导出历史，不将未经验证的包自我声明当作审核依据。

用户必须对这次预览独立确认。预览期限5分钟；授权默认2分钟、允许1秒至5分钟。墙钟和单调时钟共同校验，过期或时钟回退拒绝，不续期。并发消费在任何异步读取之前即标记已使用；读取失败、快照变化、取消、超时和Mock失败都烧毁该授权，不自动重试。再次运行必须重新预检并再次明确确认。

`mock-once`替代上面命令的`preview`时，只在真实TTY中要求输入绑定本会话的随机确认短语，不接受管道、`--yes`、授权文件或任务包中的同意字段。确认后仍只调用固定计时器Mock。没有命令/脚本/进程参数或可注入执行回调；返回`actualCodexStarted:false / actualCommandsExecuted:false / acceptanceChanged:false`。

Mock消费前只读预检与固定模拟共用最长5秒上限（界面600ms），可取消。超时会丢弃迟到的预检结果，不继续Mock；已经启动的只读Git/CLI元数据查询可能在自身超时前结束，不代表启动开发任务。

## 浏览器界面

`Codex任务交接中心 → 查看任务包与交付历史 → 单次授权与安全预检（仅Mock）`。主动选择当前任务的已导出包，预览任务、目录、范围、哈希、方式、外部操作及阻塞；然后勾选明确的单次Mock确认。可测试未授权、脏状态、HEAD变化、失败、超时和取消。

扩展没有主机文件/Git/CLI访问能力，不读取本机目录来伪装真实预检。界面的Git和CLI均显式标为Mock，固定真实执行阻塞`REAL_EXECUTOR_DISABLED / BROWSER_GIT_NOT_VERIFIED`；这不是本地CLI授权。没有从浏览器连本地执行服务的桥接。

Mock授权仅当前页面内存，刷新、关闭、恢复ZIP或更换任务不会恢复。它不写入项目、任务、交付记录、人工验收、看板或费用账本，不修改旧数据结构。远程GitHub核验、Codex声明及人工验收仍独立。

## 边界与后续风险

- 不能通过当前门禁执行真实开发。未来需要另行设计进程隔离、运行中路径白名单、出站网络/费用/外部操作控制、可信交付及持久防重放机制；`workspace-write`本身不等于允许文件范围强制执行。
- 进程内对象身份防止复制JSON伪造，不防同权限恶意代码、浏览器调试器或本机管理员修改程序。本版不声称提供跨进程/跨用户的强安全隔离。
- Git状态和范围元数据不是所有文件内容的取证证明，静态预检不能消除并发文件系统竞态；未来真实执行必须重新核对并在运行期间约束。不为通过测试放宽链接、仓库、范围或脏状态限制。
- CLI不独立读取浏览器最新审核历史；操作者的独立策略与浏览器已审核记录需对应。任务包哈希不是作者身份或执行许可。
