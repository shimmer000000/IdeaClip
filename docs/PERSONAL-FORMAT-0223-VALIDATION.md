## 诊断与边界

用户0.2.22脱敏诊断说明：模型完整返回、JSON解析通过，但首栏sections.column-1是object，Schema要求array、1～8条，因此未进入证据校验，也未保存报告。它不能证明其他栏目结构或历史validator错误原因；没有原始响应，无法恢复该次报告或核实服务商实际扣费。

检查发现personal模板只有Schema和自然语言要求，缺少此前五种模板已有的完整结构示例。本轮修复生成指导缺口，不能承诺所有真实模型都将遵循格式。继续严格拒绝无效响应，不把单对象自动包装成数组、不补齐栏目、不更改kind或证据、不自动重试付费请求。

## 实现

- 独立应用自有personal-output指导：schemaVersion:2、problem/feasibility/mvp/monetization/channels/materials/costs/risks/week/verdict十个固定key，完整数组示例；单条也必须用数组，每条仅kind/text/evidence，禁止额外包装、中文key和Markdown围栏。重申栏目内容、缺证据收入/许可、逐字引用及自检，模板内容仍位于不可信user数据。
- personal模板1.0.0→1.0.1，栏目/Schema及业务提示保持原样，仅精确原定义在读取时升级；启停、更新时间不变，不回写旧数据库行。篡改定义和未知版本不映射，旧自动授权签名不再有效。
- 新指导计入原有Token上界及费用预览，输出上限仍取配置与模板较小值；不改变模型、配置或日预算。旧报告按嵌入模板读取，旧诊断、截图、笔记、任务、孵化项目和费用账本不重写。
