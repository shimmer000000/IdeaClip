# Codex本地任务交接中心（0.1.9）

从“项目孵化中心”顶部进入“Codex任务交接中心”（`notes.html?handoff`）。此页面只处理本地数据，不安装、依赖或调用Agent Autoloop，不启动Codex进程，不执行交付报告中的命令、脚本、路径或链接。

## 已导出任务与证据

列表复用原项目中`taskPackages`和`localDeliveries`，不新建平行任务库。显示项目/任务、任务类型、仓库、包ID、生成/导出/人工交接时间、最近更新时间；可按项目、待交接/已交接/结果已导入/待人工验收/历史失效和本地日期范围筛选。每次加载最近30个项目，明确提供继续加载；列表每次展示20个包，不静默宣称已加载全部历史。

状态相互独立：

- 待交接：本机存在导出记录，未人工声明已交接；不能证明下载或执行。
- 已交接：原有人工记录，不证明Codex已执行。
- 结果已导入：包ID及内容哈希匹配的交付证据已保存，不证明开发完成。
- 待人工验收：有报告、尚无人工验收通过结论；原失败结论保留，不会被自动改为通过。

当前审核/任务内容/工作目录/范围与绑定哈希不一致、仓库不一致或ZIP恢复历史会提示包失效。**不臆造已导出包的固定时间有效期**；原10分钟限制是预览确认期限，旧包是否仍匹配当前边界另行检查。原记录没有仓库快照时明确标注“当前绑定仅供参考”；0.1.9新导出历史保存可选规范仓库字段。

点击“查看任务包与交付历史”复用原任务包与交付组件，展示完整版本历史、人工交接操作、本地测试记录文件一致性核对和复制摘要；GitHub只展示当前本机快照，不自动刷新。证据汇总分别显示Codex声明、本地文件核对、GitHub Commit/PR、CI、范围和缺口。历史/过期快照不能当最新核验，无CI不是通过或失败，文件一致性不证明测试真正执行。只有回到原项目人工确认，再明确完成任务，才会改变原状态。

## 本地收件箱

1. 用户主动选择一个目录，使用浏览器`showDirectoryPicker({mode:'read'})`。只保存当前页句柄，不枚举或读取文件内容。
2. 如果扩展页面或浏览器不支持目录能力，使用“选择候选JSON文件”，原生多选仅提供显式选择的文件；不通过后台服务绕过沙箱，不使用递归的`webkitdirectory`兜底。
3. 点击“扫描候选报告（只读）”。目录只枚举第一层最多100项；忽略子目录及非JSON，不调用子目录`values()`。只接受1～20个`.json`，单份128KiB、总计2MiB，先检查大小/数量，再逐份UTF-8和受限Schema解析；无任何JSON指令执行。
4. 收件箱只接受[交付v2协议](CODEX-TASK-PACKAGE.md#结果协议)。核对项目ID、任务ID、仓库、允许范围、已知包ID/内容SHA-256、当前绑定和报告时间。旧v1仍可在原任务中单文件导入，不能猜测它属于某个包。
5. 扫描只生成当前页候选，不写入业务库。标记“检查通过，待确认”“重复，跳过”“拒绝”；同批同ID不同内容整组拒绝；已存在同ID不同文件摘要不覆盖。任务包哈希仅为关联/完整性检查，不是报告签名或执行证明。
6. 用户逐项勾选，核对每项项目/任务/仓库及Codex声明，再明确勾选确认。可在同批选择多个项目，各项只写入它自己的任务，不能合并不同仓库证据。10分钟候选预览过期须重新扫描。
7. 确认时使用已扫描的冻结文本，重新核对最新绑定，再复用原`importCodexReport`事务追加。绑定改变、任务缺失、哈希错误等按项拒绝；相同报告只保存一次。显示成功/跳过/失败数量和各项原因，不自动重试，不回滚已独立成功的其他项目，不自动验收或完成。
8. 关闭页面会丢弃目录句柄、文件选择、候选和确认。重新打开只能查看已保存报告/历史，必须重新选目录并主动扫描；不存在后台监听、文件路径访问或自动执行授权。

## 存储与兼容

沿用Dexie schema14、ZIP6。已有笔记、图片、项目、任务、报告、人工验收及预算记录不迁移、不重建、不删除。新历史的`repository?`是允许备份的公开业务引用；所有历史与v2关联仍通过原ZIP白名单校验，恢复强制历史，不恢复workspace、审核或任何执行资格。目录句柄、候选原文、绝对文件路径和授权均不持久化、不进入ZIP。

仅使用现有React/Dexie/Playwright依赖，无新浏览器主机权限、不访问服务器或付费API。真实用户环境测试只对独立合成验收任务追加明确标注的Mock证据；不能把这些报告称为真实产品开发或真实API测试通过。
