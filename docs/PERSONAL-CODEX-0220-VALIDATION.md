## 使用步骤

1. 灵感管理中心→GitHub项目分析，输入完整仓库并主动获取资料，或在「使用已保存公开资料」中选择历史快照。
2. 「分析模式」选择普通变现推广分析或个人 + Codex 创业分析；普通模式保留原八栏，个人模式新增独立十栏。
3. 可选填写实际成本，生成个人Codex免费规则报告。新笔记/报告单独追加，不自动请求GitHub或AI，不进入自动队列。
4. 打开报告：默认十栏折叠，可全部/独立展开，复制/导出带来源的全文、重开查看历史。AI深度分析通过原「预览发送内容」检查模型、资料、Token和预计费用，单次确认后发送，不自动重试。
5. 报告底部点击「生成最小可用产品开发方案」，审核/修改MVP功能、技术难点风险及可检查的验收标准，勾选人工审核后确认创建，再进入既有孵化中心。编辑任一字段清除确认，来源改变/删除拒绝创建，同一报告重复确认返回已有MVP草案。草案没有任务执行授权，也未自动绑定目录、创建仓库或发布。

## 十栏及规则边界

项目解决的真实问题；我能不能使用Codex完成；1～2天最小产品方案；最适合我的变现方式；推广方式分析；原创推广素材；成本与利润；风险与许可证；7天真实需求验证；是否值得开发。

独立builtin-personal 1.0.0，旧六模板定义不变。全部免费规则结论为待验证假设，AI模式仍有严格Schema/逐字证据/费用门禁。源码、依赖、Windows兼容性未实际安装审计；轻量项目也不能保证两天，复杂GPU/分布式/多租户/登录信号明确超期并缩为演示/人工样品。A/B/C/D为建议，免费规则保守使用B/C/D，材料不够不自动给A。

六项评分为需求25%、Codex可行性20%、推广20%、变现15%、维护10%、许可合规10%。免费规则仅对README存在的粗略信号给1～2/5的假设估分，逐项附README片段或缺口；真实需求/变现/完整合规无证据则未知。覆盖0/6或3/6（权重0%或50%）仅代表规则信号，不代表真实证实程度、获利概率或完整技术审计，不输出精确总分。AI要求逐项0～5或未知及来源/缺口，不宣称能机械识别所有语义幻觉，仍需人工核实。

按关键词在生活图像类选择小红书/抖音，其余技术或未知受众先B站/GitHub并明确待验证；不无条件全选渠道。原创三选题/标题、30秒脚本、功能/行动引导/指标仅为草稿，不发布。价格49～99元仅为规则访谈测试假设，不是成交或实际客单价。

人工成本独立保存开发测试小时、API费用、服务器元/月、域名部署元/年、支持小时/周、推广费用、支付费率。空白未知，非负有限十进制、最多两位小数，费率0～100%；不同周期不直接相加。无实际收入/利润/客户/转化率证据。用户填报不等于独立核验；AI发送预览含本次成本，可取消。

许可证仅从现有快照中README之前的元数据读标识，README伪造license不升级权限。未知、GPL/AGPL/非商业限制及敏感数据分别提示；商业使用、二次分发、托管、依赖、素材、商标、模型条款和平台规则都需核实。此处不作法律许可结论。
