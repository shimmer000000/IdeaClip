# AI分析失败诊断（0.2.4）

适用于单篇已保存笔记的“AI 商业模式分析”页面。失败后点击“查看诊断报告”。此操作只读取本机记录；不会重发模型请求，也不重试 Brave 或 DeepSeek。

## 如何排查

1. 看阶段和安全错误码，确认是响应接收、JSON、Schema、来源证据还是本地保存。
2. 看固定失败字段、校验规则、期望与实际类型、数组/字符数量、栏目/条目序号。业务15栏使用实际构建时Ajv验证器的第一个错误；自定义模板使用现有严格校验器，路径转为栏目序号，隐藏自定义名称。
3. 看“请求、响应与保存状态”。“未知”表示未执行该阶段或没有记录，不表示通过。响应已读取与模型输出完整是两个状态；后者只依据实际finish_reason，length明确为截断。
4. 看实际Token与本地预留。未取得usage显示未知；估算输入、最大输出、本地预算预留不等于实际Token或服务商扣费。真实扣费仍须服务商账单核对。
5. 复制脱敏摘要或“给Codex的修复指令”，先使用Mock复现。诊断不会自动上传；任何新的付费重试仍需用户逐次确认。

## 诊断字段与边界

`IdeaClipAIDiagnostic/schemaVersion=1`为导出格式。包含本地诊断/尝试ID、时间、应用版本、分析类型、内置模板名称/版本、受限模型名、固定阶段/错误说明、首个安全失败点、三态检查、实际取得的finish_reason/usage、本地预留与建议。未知类型或不可信名称不会原样输出。导出不含笔记ID、URL、正文、完整响应、引用、截图、Header、Cookie、Key或本机工作目录；自定义模板名隐藏。

固定错误包括：字段缺失/额外字段、类型错误、Schema版本错误、栏目为空/超量、字符长度超限、证据缺失/不匹配、来源快照变化、本地验证器/格式化异常、空内容、截断、外层/内层JSON失败、读取/UTF-8失败与本地保存失败。未知异常只记固定本地错误，不保存异常原文。

单笔记协议使用`kind/text/evidence`，fact只是来源陈述，并非独立核实事实；其evidence必须非空且为已发送文本的连续逐字子串，不统一换行、空白或Unicode。单笔记不存在sourceId/quote/original字段，模型返回它们会作为额外字段拒绝。深度研究协议独立区分不存在/不可读/缺失的sourceId、quote缺失/不匹配、original与quote不相同；不会把研究规则错误套在单篇笔记上。

## 保存、历史与隐私

Dexie版本15仅增加`aiDiagnostics`，全机保留最近20条安全元数据。每条关联当次分析；失败后即写入，关闭重开可查。写入失败时当前页面仍可显示/导出，并明确提示未确认持久化。诊断单独存于本机，不纳入普通ZIP；恢复ZIP不恢复执行授权，也不清空诊断或费用账本。

如果模型有效结果仍在内存而本地保存失败，页面提供“重试保存分析结果”，只调用本地save。成功后诊断保存状态更新；当时内存保留不保证关闭后仍能恢复。诊断不会持久保存原始模型响应作为恢复副本。

“删除本笔记诊断历史”有明确确认，只删除诊断表对应记录，不删分析报告、笔记或账本。旧费用记录中的失败摘要仍可只读查看。旧错误没有记录详细响应/字段/finish_reason时显示“历史信息不足，无法定位具体字段”，不能事后推断原因或补造报告。
